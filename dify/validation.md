# 验证样例与运行证据

本文件给出可直接按步骤复现的验证样例。作品的核心能力是「跨会话记住玩家」，因此用两个独立会话验证。

## 一、准备

1. 按 `README.md` 启动后端：`uvicorn app:app --host 0.0.0.0 --port 8099`。
2. 在 Dify 中导入 `dsl/memory-tavern.yml`，绑定一个可用的 Chat 模型。
3. 使用同一个 Dify 用户身份（`sys.user_id` 固定）进行两个会话。Dify 的“新建对话”按钮即可产生新会话，但用户身份不变。

## 二、样例 A：建立记忆（第一次会话）

**初始状态**：全新用户，`backend/data/memory_tavern.db` 中没有该用户的 Memory。

**输入 1**：

> 我叫阿岚，是一名迷路的旅人，最喜欢桂花酿。身上只剩一枚铜币，先欠着酒钱吧。

**预期表现**：

- 阿墨以酒馆掌柜口吻回应，称呼“阿岚”。
- 会提到桂花酿或那枚铜币，语言自然，不出现“记忆库/系统”等词。

**后端记录**：Dify 的「记住这一轮」节点调用 `POST /remember`，返回类似：

```json
{"status":"saved","entry_id":"mem_ent_53037e7d49914c57a45f21f7c52965fd","memory_artifact_id":"memory"}
```

**输入 2**（同一会话继续）：

> 给我讲讲雾港的故事吧，我想在那里找一条船。

**预期表现**：阿墨讲一个具体的雾港小故事，并在结尾把话题抛回给阿岚（例如问她要去哪里）。

## 三、样例 B：跨会话召回（第二次会话）

**初始状态**：点击「新建对话」，同一 Dify 用户；后端数据库保留上一节写入的 Memory。

**输入**：

> 掌柜的，还记得我吗？我叫什么名字？我最喜欢喝什么？

**预期表现**：

- 阿墨应当先叫出“阿岚”。
- 应当提到“桂花酿”。
- 可以顺带提到“一枚铜币”的欠账（属于加分表现，允许因召回数量上限而不出现）。

**技术核对**：

- Dify 的「召回记忆」节点调用 `POST /recall`，后端返回的纯文本中包含 `阿岚` 与 `桂花酿`。
- 该文本被拼进 LLM 系统提示词，因此回答有据可查，不是模型自由发挥。

## 四、后端冒烟测试（无需 Dify）

在 `backend/` 目录执行：

```bash
python smoke_test.py
```

预期输出：

```text
- 玩家说：我叫阿岚，我最喜欢桂花酿，还欠你一枚铜币。
掌柜回应：阿岚，桂花酿给你留着，铜币的事我也记着。

SMOKE TEST PASSED
```

该测试使用真实的 PowerContext `open_builtin_runtime`（SQLite 持久化），完整走通 `remember → recall` 链路。

## 五、实际运行记录

本仓库交付前已在 Windows + Python 3.13 环境执行上述冒烟测试，实测输出：

```text
health: {'status': 'ok'}
recall empty: 200 （还没有关于这位玩家的记忆。这是你们第一次见面。）
remember: 200 {'status': 'saved', 'entry_id': 'mem_ent_53037e7d49914c57a45f21f7c52965fd', 'memory_artifact_id': 'memory'}
recall after: 200 - 玩家说：我叫阿岚，是一名迷路的旅人。
掌柜回应：阿岚，这个名字我记下了。先喝杯热酒吧。
```

结论：空记忆时的兜底话术、写入成功回执、写入后按查询召回均符合预期。

## 六、恢复初始状态

- 想清空全部记忆：停止后端，删除 `backend/data/memory_tavern.db`，再启动。
- 想保留旧数据但开新故事：在 Dify 中使用新的用户身份，或用新 `player_id` 直接调用后端接口。
